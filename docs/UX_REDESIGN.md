# Shorts Studio 단일 화면 UX 재설계안

작성일: 2026-10-13

## 검토 결과

현재 Windows 앱은 `ui/desktop.py`의 Tkinter 화면에 입력·변환·분석·소싱·상품·업로드 버튼이 흩어져 있고, 설정은 기능마다 별도 팝업으로 열린다. `ui/web.py`는 Streamlit 기반 Core 변환 데모라서 나머지 모듈을 확인하거나 편집할 수 없다. 따라서 현재 UI를 다듬는 것만으로는 “설정부터 최종 결과까지 한 화면에서 확인”하는 UX를 만들기 어렵다.

권장 방향은 Python Core/기능 모듈을 유지하면서 Windows 앱에 로컬 웹 UI를 제공하는 것이다. 앱을 실행하면 브라우저형 작업 공간이 열리고, 제작 진행 상태와 모든 단계 산출물이 같은 작업 화면에 누적된다. 설정은 화면 상단의 상태 요약과 접이식 설정 패널에서 다룬다.

## 기본 화면 구성

기준 해상도는 PC 1440×900이며, 작은 화면에서는 우측 미리보기 패널을 아래로 이동한다. 모바일 세로 화면은 편집·상태 확인을 지원하고, 긴 작업이나 타임라인 편집은 PC 사용을 우선한다.

```text
┌ Shorts Studio ─ 작업 이름 ─ 저장됨 ─ Provider 상태 ─ 작업 기록 ─ 설정 ┐
├────────────── 제작 파이프라인 상태 바 ──────────────────────────────┤
│ ① 소스  → ② 문자 제거  → ③ 분석·대본  → ④ 음성·자막  → ⑤ 상품·내보내기 │
├──────────────────────────────────────┬──────────────────────────────┤
│ 작업 편집 영역                        │ 결과 미리보기                 │
│                                      │ 원본 / 문자 제거 비교          │
│ [YouTube/TikTok URL 또는 파일]        │ 9:16 영상 플레이어             │
│ [소스 후보 검색]                      │ 현재 단계 산출물 선택           │
│                                      │ 처리 정보 · 경고 · 다운로드     │
│ [화면 비율] [pad/crop] [문자 제거 필수]│                              │
│                                      │                              │
│ 단계별 카드: 결과·편집·재실행          │                              │
├──────────────────────────────────────┴──────────────────────────────┤
│ 진행률 · 현재 단계 · 취소 · 마지막 저장 상태 · [제작/다음 단계]        │
└─────────────────────────────────────────────────────────────────────┘
```

### 상단 작업 바

- 작업 이름, 자동 저장 상태, 작업 기록 열기, 전체 설정 진입점을 고정한다.
- Provider/TTS/YouTube/Coupang 자격 증명은 `연결됨`, `설정 필요`, `확인 필요` 상태만 노출한다. 실제 key 값은 브라우저에 표시하거나 저장하지 않는다.
- “새 작업”과 “작업 불러오기”로 로컬 작업 기록을 이어서 편집한다.

### 파이프라인 상태 바

- 각 단계에 `대기`, `실행 중`, `완료`, `검토 필요`, `실패`를 표시한다.
- 완료된 단계는 산출물이 있음을 보여주며 클릭하면 해당 카드와 미리보기로 이동한다.
- 문자 제거는 필수 단계로 고정한다. 실패하거나 결과 검토 전이면 후속 음성·자막 제작을 진행하지 않도록 한다.
- 단계 재실행은 해당 단계와 그 이후 산출물만 무효화한다. 원본과 앞 단계 산출물은 유지한다.

### 왼쪽 작업 편집 영역

1. **소스**: YouTube/TikTok URL 또는 로컬 파일, 소스 검색, 다운로드 상태와 출처 정보.
2. **Core 설정**: 9:16, pad/crop, 출력 위치·품질. 고급 FFmpeg 옵션은 접어서 둔다.
3. **문자 제거**: 언어 구분 없는 전체 화면 처리 상태, 탐지 크기/품질 preset, 프레임 수·처리 시간. 비교 화면에서 원본/마스크/결과를 전환한다.
4. **AI 분석·한국어 대본**: 분석 요약과 구간 목록, 대본 편집기, 길이·톤·CTA, 재생성 버튼.
5. **음성·자막**: Provider/Voice 상태, 속도, 문장별 자막과 시작·종료 시각, 미리 듣기·재합성.
6. **상품·내보내기**: Coupang 후보 검색과 선택, 제목·설명·태그·공개 범위, 업로드 전 최종 확인.

단계 카드는 결과가 생기면 요약을 보여주고, 설정/편집 폼은 펼쳤을 때만 표시한다. 화면에 단계가 계속 보여도 완료된 카드가 긴 입력 폼으로 작업 공간을 밀어내지 않게 한다.

### 오른쪽 결과 패널

- 선택된 단계의 결과를 바로 재생한다. 문자 제거 단계에서는 원본과 처리 결과를 동일 시점으로 맞춰 비교한다.
- 결과별 파일명, 해상도, 길이, 오디오 유무, 생성 시각, 경고를 표시한다.
- 산출물 목록에서 `원본 다운로드`, `무음 변환본`, `문자 제거본`, `최종 음성·자막본`, `업로드 영수증`을 선택한다. 아직 생성되지 않은 항목은 비활성화하고 필요한 선행 단계만 안내한다.
- 문자가 남거나 복원이 거친 프레임은 `검토 필요`로 표시하고 비교 미리보기로 연결한다.

### 하단 고정 작업 바

- 작업 중에는 단계명, 퍼센트, 경과 시간, 취소를 고정 표시한다.
- idle 상태의 주 버튼은 현재 준비 상태에 따라 `문자 제거 시작`, `분석 및 대본 생성`, `음성·자막 합성`, `최종 영상 저장`처럼 다음 가능한 작업을 설명한다.
- API 호출, 다운로드, 업로드처럼 외부 동작은 비용/공개 범위가 달라지는 시점에 실행 전에 확인한다.

## 설정 UX

일상 작업에 필요한 설정은 화면 내에서 노출하고, AI 분석 Provider·대본 전용 Gemini·TTS·소싱·Coupang·업데이트 설정은 우측 설정 drawer에서 탭으로 정리한다. API secrets는 Windows Credential Manager에 저장하고, TTS는 Windows Heami local voice를 사용하므로 API key 설정은 없다. Gemini API Key는 Google AI Studio에서 만들며 대본 설정 탭에서 저장·연결 확인한다.

## 기술 구조 제안

- UI: 반응형 HTML/CSS/JavaScript 단일 페이지 앱. 초기 구현은 빌드 체인과 런타임 의존성을 추가하지 않으며, 작업 카드와 비디오 미리보기/비교를 담당한다.
- 로컬 API: Python 표준 라이브러리 `http.server`가 Python `pipeline`을 실행한다. 기능 범위가 커져 요청/인증/API 구조가 복잡해질 때 FastAPI 도입을 검토한다. 결과와 job state는 기존 Python 모듈을 단일 진실 공급원으로 유지한다.
- 진행 이벤트: 장시간 작업의 진행률/로그는 SSE로 전달하고, 취소는 job cancel endpoint로 처리한다.
- Windows 배포: PyInstaller 앱이 API와 정적 UI를 함께 실행하고 기본 브라우저 또는 앱 창을 연다. 처음에는 `127.0.0.1`에만 bind한다. 다른 기기에서 접속하는 기능은 인증·세션 보호를 설계한 별도 단계로 둔다.
- Streamlit은 개발용 Core 테스트 진입점으로 남길 수 있으나, 사용자용 전체 UX의 기준 화면은 새 웹 UI로 통합한다.

## 구현 순서와 완료 기준

1. **Shell과 작업 화면**: FastAPI 정적 제공, 반응형 레이아웃, 단계 상태 바, 작업 생성/불러오기. 완료 기준은 가짜 job 데이터로 PC/모바일 크기에서 상태와 카드 배치 확인.
2. **Core + 문자 제거 연결**: URL/파일 입력, 처리 진행·취소, 비교 미리보기, 산출물 메타데이터. 기존 Core 테스트와 실제 `111.mp4` 수동 품질 확인을 별도로 유지.
3. **AI·대본·TTS 편집 연결**: 분석 및 대본 편집, 자막/음성 미리보기, 단계 재실행 시 후속 산출물 무효화 확인.
4. **상품·업로드·설정 drawer 연결**: 기존 adapter와 자격 증명 저장을 재사용하고 승인된 계정이 필요한 테스트는 수동 검증.
5. **Windows 설치형 마감**: 로컬 전용 API, 앱 실행·종료, 브라우저 복구, 업데이트 패키징, clean Windows 설치 테스트.

**현재 구현:** 반응형 단일 화면, URL/파일 업로드, Core·필수 문자 제거, AI 분석과 편집 가능한 분석 JSON, Gemini API 한국어 대본 생성/편집, TTS·SRT 합성, Coupang 후보 검색 및 대본 연결, YouTube metadata·OAuth·업로드를 작업 화면에 연결했다. Gemini 전용 API Key/model 저장과 연결 확인도 drawer에 추가했다. 실제 사용자 API Key와 생성 품질 검증은 별도 수동 테스트로 남는다.

## 확인이 필요한 제품 결정

현재 설치형 앱의 기본 접근은 같은 Windows PC의 브라우저로 한정한다. Android에서 직접 접속하는 LAN 모드는 로컬 API 인증, PC 주소 변경, 방화벽 허용 UX가 추가로 필요하므로 기본값에 포함하지 않는다. 기존 모듈에 이미 있는 URL 입력, 문자 제거 필수 정책, 작업 기록, Provider key 보호를 활용하며, 화면 단계별 산출물을 한 작업 안에서 확인하고 이어서 편집할 수 있다.
